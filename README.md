# attendancem

勤怠打刻ツール。ボタン1タップで自分の Google カレンダーに打刻の予定を作成し、
設定した2名を招待する。

打刻は6種別ある。出社・退社は**リアルとリモートを区別する**。

| ボタン | カレンダー上のタイトル | 招待メール |
|--------|---------------------|-----------|
| リアル出社 | `リアル出社_{氏名}` | 送る |
| リモート出社 | `リモート出社_{氏名}` | 送る |
| リアル退社 | `リアル退社_{氏名}` | 送る |
| リモート退社 | `リモート退社_{氏名}` | 送る |
| 休憩開始 | `休憩開始_{氏名}` | **送らない** |
| 休憩終了 | `休憩終了_{氏名}` | **送らない** |

タイトルに氏名を含めるのは、招待先の共通カレンダー上で誰の打刻かを
タイトルだけで判別できるようにするため（[ADR-0023](./ADR.md#adr-0023)）。
氏名は初回に画面から設定する。**未設定のままでは打刻できない。**

休憩は招待者に追加されるがメールは飛ばない。招待先のカレンダーには表示されるため、
実働時間から休憩を差し引く計算はできる（[ADR-0020](./ADR.md#adr-0020)）。

Google Apps Script の Web App として動作する。サーバー不要・費用0円。

## 構成

```
src/
├── appsscript.json   マニフェスト（TZ・OAuth スコープ・Web App 設定）
├── Config.gs         設定値と、挙動を切り替える定数
├── Code.gs           サーバーロジック（doGet / getStatus / punch）
└── index.html        UI（HTML + CSS + JS を1ファイルに同梱）
```

## セットアップ

### 1. GAS プロジェクトを作る

**clasp を使う場合（推奨）**

clasp はグローバルにインストールしない。プロジェクト内に閉じ込める（[ADR-0012](./ADR.md#adr-0012)）。

```bash
npm install                # node_modules/ に clasp を導入する
npm run login              # ブラウザが開く。認証情報は ./.clasprc.json に保存される
npm run create             # GAS プロジェクトを作成する（.clasp.json が生成される）
# → .clasp.json の "rootDir" を ".gas-init" から "src" に書き換え、rm -rf .gas-init
npm run push -- --force    # src/ の4ファイルを反映する
```

`npm run create` は事前に [Apps Script API の有効化](https://script.google.com/home/usersettings)
（「Google Apps Script API」を ON）が必要。OFF のままだとエラーになる。

> **⚠️ なぜ `create` の後に `rootDir` を書き換えるのか**
>
> `clasp create` はひな形マニフェストを `rootDir` に clone する。`--rootDir ./src` を
> 指定すると **既存の `src/appsscript.json` が `America/New_York` の既定値で潰され**、
> そのまま push すると ADR-0007（Asia/Tokyo 固定）と ADR-0002（自分のみアクセス）が
> 両方とも失われる。2026-08-05 に実際に起きた事故である。
>
> そのため `npm run create` は clone 先を捨てディレクトリ `.gas-init` に向けてある
> （[ADR-0015](./ADR.md#adr-0015)）。`src/` には触れないので、後から `rootDir` を
> `src` に戻せばよい。**`--rootDir ./src` に書き換えないこと。**
>
> push の前に `src/appsscript.json` を必ず確認する。`timeZone` が `Asia/Tokyo` で、
> `webapp` と `oauthScopes` があること。潰れていたら復元してから push する。
>
> ```bash
> git checkout HEAD -- src/appsscript.json   # コミットしてあれば一発で戻る
> npm run push -- --force                    # マニフェストの上書きには --force が要る
> ```

`create` がその他のひな形ファイルを生成した場合は削除してから `push` する
（`src/` の4ファイルだけが残る状態にする）。

以降の反映は `npm run push` だけでよい。他のコマンドは `npm run clasp -- <サブコマンド>` で叩く。

| コマンド | 内容 |
|---------|------|
| `npm run push` | `src/` を GAS に反映 |
| `npm run status` | push 対象のファイル一覧を確認 |
| `npm run open` | GAS エディタをブラウザで開く |
| `npm run whoami` | 現在の認証状態を確認 |
| `npm run logout` | `.clasprc.json` を破棄 |

**撤去したくなったら**

```bash
npm run logout
rm -rf node_modules package-lock.json .clasprc.json .clasp.json
```

グローバル環境には何も残らない。

**エディタに手で貼る場合**

1. [script.google.com](https://script.google.com) で新しいプロジェクトを作成し、名前を `attendancem` にする
2. 「プロジェクトの設定」で **「`appsscript.json` マニフェスト ファイルをエディタで表示する」をON**
3. 以下のファイルを作成し、`src/` の内容を貼り付ける
   - `appsscript.json`（既存のものを上書き）
   - `Code.gs`（既定の `コード.gs` をリネーム）
   - `Config.gs`（スクリプトファイルとして追加）
   - `index.html`（**HTML ファイル**として追加。拡張子は自動で付くので名前は `index`）

### 2. 招待先を設定する

「プロジェクトの設定 > スクリプト プロパティ」で以下を追加する。

| プロパティ | 値 |
|-----------|-----|
| `GUEST_EMAILS` | `aaa@gmail.com,bbb@gmail.com` |

カンマ区切り。空白は自動で除去される。
メールアドレスはソースコードに書かない（[ADR-0009](./ADR.md#adr-0009)）。

### 3. 氏名を設定する

打刻のタイトルは `{種別名}_{氏名}` 形式であり、**氏名が未設定だと打刻できない**。
氏名は Script Properties ではなく **User Properties** に入るため、
「プロジェクトの設定」の画面からは設定できない（[ADR-0024](./ADR.md#adr-0024)）。

エディタで **デプロイ > デプロイをテスト** の URL（`/dev` で終わる）を開き、
画面上部の入力欄に氏名を入力して保存する。本番デプロイはまだ不要である。

エディタから設定したい場合は `setupDisplayName('山田太郎')` を使う。
GAS エディタの「実行」は引数を渡せないため、この関数は clasp 経由などで呼ぶ。

### 4. 動作確認

エディタで以下を順に実行する。初回は OAuth の承認画面が出るので許可する。

| 関数 | 確認内容 |
|------|---------|
| `checkConfig()` | 実行ログに `guests` が2件、`displayName` に氏名が出て、`error` が `null` であること |
| `testTransitions()` | 実行ログが `失敗 0 件` であること。カレンダーには何も書き込まれない |
| `testTitles()` | 実行ログが `失敗 0 件` であること。カレンダーには何も書き込まれない |
| `testPunchOfficeIn()` | カレンダーに `リアル出社_{氏名}` が作成され、2名に招待メールが届くこと |
| `testPunchBreakIn()` | `休憩開始_{氏名}` が作成され、**招待メールは届かない**こと |
| `testPunchBreakOut()` | `休憩終了_{氏名}` が作成されること |
| `testPunchOfficeOut()` | `リアル退社_{氏名}` が作成され、2名に招待メールが届くこと |

`testPunchRemoteIn()` / `testPunchRemoteOut()` も同様に用意してある。

GAS エディタの「実行」は関数に引数を渡せないため、`punch('officeIn')` は直接実行できない。
上記のラッパー関数を使う。

**実行順に意味がある。** 勤務外の状態でいきなり `testPunchOfficeOut()` を実行しても、
状態遷移チェックに弾かれてイベントは作成されない（それが正しい挙動である）。
上の表の順に実行すること。

**各打刻の間は1分以上あける。** 直前の打刻から1分未満の打刻は種別を問わず拒否される
（連打しきい値。[ADR-0019](./ADR.md#adr-0019)）。

`testTransitions()` は勤務状態の遷移表を、`testTitles()` はタイトルの生成と
種別判定を検証する自動テストで、どちらもカレンダーにも招待メールにも一切触れない
（[ADR-0021](./ADR.md#adr-0021)）。最初に通しておくと、
以降の打刻が拒否されたときに「遷移表やタイトル判定の誤り」を切り分け対象から外せる。

確認で作成した予定は、カレンダーから削除しておく。

### 5. デプロイ

「デプロイ > 新しいデプロイ」→ 種類「ウェブアプリ」を選び、以下を確認してデプロイする。

- **次のユーザーとして実行**: 自分
- **アクセスできるユーザー**: 自分のみ

この2つが [ADR-0002](./ADR.md#adr-0002) の前提であり、変えると URL を知る他人が
打刻できるようになる。`appsscript.json` に同じ設定が入っているため、通常は初期値のままでよい。

発行された Web App URL を控える。

### 6. ホーム画面に追加（iPhone）

Safari で Web App URL を開き、共有ボタン →「ホーム画面に追加」。
これでホーム画面から2タップで打刻できる（PLAN.md 非機能要件 N-2）。

## 使い方

画面を開くと、当日の打刻履歴と現在の勤務状態が表示される。
ボタンを押すと現在時刻で予定が作成される。

### 押せるボタンは勤務状態で決まる

状態は打刻の履歴から毎回導き出される。状態そのものはどこにも保存していない。

| 現在の状態 | 押せるボタン |
|-----------|------------|
| 勤務外（初期状態 / 退社済み） | リアル出社・リモート出社 |
| 勤務中 | リアル退社・リモート退社・休憩開始 |
| 休憩中 | 休憩終了 |

押せないボタンは非活性になる。6つのボタンは常に同じ位置に表示され、
状態によって並びが変わることはない（[ADR-0022](./ADR.md#adr-0022)）。

- **同じ日に何度でも出社・退社できる。** 退社した後、同じ日にまた出社してよい
- **出社と退社の形態は一致しなくてよい。** リアル出社してリモート退社できる
- **休憩を閉じないと退社できない。** 休憩中の退社は拒否される。
  先に「休憩終了」を押す。休憩が開いたままだと招待先が実働時間を計算できないため
- **直前の打刻から1分間は、種別を問わず打刻できない。** 誤タップと連打への対策
- **氏名が未設定だと打刻できない。** 画面の入力欄から設定する。
  氏名なしのタイトルは打刻として認識されないため、作成しても履歴にも状態にも現れない
- 日付を跨いだ勤務にも対応している。22:00 に出社して翌 01:00 に退社できる。
  このとき履歴は当日分だけが表示されるため、**履歴が空なのに「勤務中」と出るのは正常**

### 打刻を間違えたとき

**Google カレンダーから該当の予定を削除する。** アプリ側に取り消し機能はない
（[ADR-0019](./ADR.md#adr-0019)）。

削除すると勤務状態も自動的に巻き戻る。カレンダーが唯一の記録先であり、
状態はそこから毎回導出されるためである。

- 出社・退社の予定を削除すると、招待者2名に**キャンセル通知が届く**
- 休憩の予定を削除しても通知は飛ばない（そもそも招待メールを送っていないため）
- 打刻時刻がずれただけなら、カレンダー上で予定の時刻を直せばよい
- **種別を間違えた場合**（リアル出社のつもりでリモート出社）は、予定のタイトルを
  正しいものに書き換えてもよい。タイトルが種別判定のキーであるため、
  上の表の形式に沿っていれば履歴にも状態にも正しく反映される

**タイトルを手で編集するときの規則**（[ADR-0023](./ADR.md#adr-0023)）

打刻として認識されるのは、**最初の `_` より前が種別名と完全に一致する**タイトルだけである。

| タイトル | 結果 |
|---------|------|
| `リアル出社_山田太郎` | 打刻として認識される |
| `リアル出社_山田_太郎` | 認識される（氏名側の `_` は問題ない） |
| `リアル出社` | **認識されない**（`_` と氏名が必要） |
| `リアル出社について_打ち合わせ` | 認識されない |

`_` を消したり種別名を1文字でも変えたりすると、**その打刻はツールから見えなくなる**。
カレンダー上には残るが、履歴にも勤務状態にも反映されなくなる。

## 設定変更

### 招待先を変える

「スクリプト プロパティ」の `GUEST_EMAILS` を書き換える。**再デプロイは不要。**

### 氏名を変える

画面の入力欄から設定し直す。**再デプロイは不要。**

**過去のイベントのタイトルは書き換わらない。** カレンダー上に新旧の氏名が混在するが、
種別判定は最初の `_` より前だけを見るため、履歴にも勤務状態にも影響しない。
過去分も揃えたい場合は Google カレンダーで手作業で直す。

氏名は20文字以内。前後の空白は除去される。改行やタブは使えない。

### 招待メールを止める

送信可否は打刻種別ごとに持たせてある。`src/Config.gs` の `PUNCH_TYPES` で
止めたい種別の `sendInvites` を `false` にして再デプロイする。

```js
officeIn: {
  key: 'officeIn',
  title: 'リアル出社',
  sendInvites: false,   // ← ここ
  ...
},
```

全部止めるなら6箇所すべてを `false` にする。単一フラグ `SEND_INVITES` は廃止した
（[ADR-0020](./ADR.md#adr-0020)）。休憩の2種別は既定で `false` である。

メールは飛ばなくなるが、招待先のカレンダーには予定として表示される。

### 連打しきい値・状態導出の窓を変える

`src/Config.gs` の以下の定数を変えて再デプロイする。

| 定数 | 既定値 | 用途 |
|------|-------|------|
| `MIN_PUNCH_INTERVAL_MS` | `60 * 1000` | この時間内の打刻を種別を問わず拒否する |
| `STATE_LOOKBACK_DAYS` | `1` | 勤務状態を何日前の 0:00 まで遡って導出するか |

`STATE_LOOKBACK_DAYS` を `0` にすると当日 0:00 が起点になり、
**日を跨いだ勤務の退社が「勤務外からの退社」として拒否される**（[ADR-0018](./ADR.md#adr-0018)）。
日数であって時間幅ではない。

### コード変更を反映する

**手順の全体は [DEPLOY.md](./DEPLOY.md) にまとまっている。** 以下は要点のみ。

GAS はコードを保存しただけでは Web App に反映されない。
`npm run push` も**デプロイではない**（GAS プロジェクトへの転送であり、本番 URL は変わらない）。

```bash
npm run push -- --force   # GAS へ転送。この時点では本番は変わらない
```

そのうえで「デプロイ > デプロイを管理」→ 対象デプロイの鉛筆アイコン →
バージョンを「新バージョン」にして「デプロイ」。

**URL を変えたくないので、「新しいデプロイ」ではなく既存デプロイの編集を使う。**
新しいデプロイを作ると URL が変わり、ホーム画面のアイコンが古いバージョンを指したままになる
（[ADR-0016](./ADR.md#adr-0016)）。

## トラブルシュート

| 症状 | 原因と対処 |
|------|-----------|
| 「招待先が未設定です」と表示される | スクリプト プロパティに `GUEST_EMAILS` を設定する |
| 「氏名が未設定です」と表示される | 画面の入力欄から氏名を設定する。スクリプト プロパティではなく User Properties に入るため、「プロジェクトの設定」の画面には現れない（[ADR-0024](./ADR.md#adr-0024)） |
| 打刻したのに履歴に出ない | タイトルが `{種別名}_{氏名}` 形式か確認する。手で編集して `_` を消した、または種別名を変えた可能性がある（[ADR-0023](./ADR.md#adr-0023)） |
| 氏名なしの古い打刻が履歴から消えた | **仕様。** 氏名なしのタイトルは打刻として認識しない。移行もしない（[ADR-0023](./ADR.md#adr-0023)）。カレンダー本体には残っている |
| 招待メールが届かない | 迷惑メールを確認。休憩の2種別は**仕様として送らない**（[ADR-0020](./ADR.md#adr-0020)）。出社・退社で届かないなら `PUNCH_TYPES` の `sendInvites` が `false` になっていないか確認 |
| 意図しないカレンダーに予定ができる | `Code.gs` の `getCalendar()` が `CalendarApp.getDefaultCalendar()` を返している。特定のカレンダーを使うなら `CalendarApp.getCalendarById('...')` に変更する |
| 打刻時刻が9時間ずれる | `appsscript.json` の `timeZone` が `Asia/Tokyo` か確認（[ADR-0007](./ADR.md#adr-0007)） |
| 「勤務外です」「勤務中です」「休憩中です」と出て打刻できない | 現在の勤務状態から遷移できない打刻を押している。画面上部のバッジで状態を確認する。状態がカレンダーの実態と食い違う場合は、当日または前日のカレンダーに打刻タイトルと完全一致する予定が別途ないか確認する |
| 「直前の打刻から1分経過していません」と出る | 連打しきい値。1分待ってから押す（[ADR-0019](./ADR.md#adr-0019)）。正当な操作で頻繁に当たるなら `MIN_PUNCH_INTERVAL_MS` を下げる |
| 履歴が空なのに「勤務中」と表示される | **日を跨いだ勤務では正常。** 履歴は当日分のみ、状態は前日 0:00 からの範囲で導出している（[ADR-0018](./ADR.md#adr-0018)） |
| 出社を打ち忘れた日に退社が打てない | 勤務外からの退社は拒否される。カレンダーに出社の予定を手で作成（タイトルを完全一致させる）してから退社を打つ |
| ボタンがすべて非活性のまま | 画面上部に赤いバナーが出ていないか、氏名が未設定になっていないか確認する。`Status.error` があるとき、および氏名が未設定のときは全ボタンを止めている |
| コードを直したのに画面が変わらない | 既存デプロイを「新バージョン」で更新する（上記「コード変更を反映する」） |
| 権限エラーが出る | OAuth スコープを変更した場合は再承認が必要。エディタで任意の関数を実行して承認し直す |
| 「他の処理を実行中です」と出る | 前回の処理がロックを保持している。数秒待って再実行する |

## 月次の集計について

集計機能は意図的に実装していない（[ADR-0010](./ADR.md#adr-0010)）。

Google カレンダー連携を設定した AI アシスタントに、対象月と
6種別の予定タイトル（`リアル出社_{氏名}` / `リモート出社_{氏名}` / `リアル退社_{氏名}` /
`リモート退社_{氏名}` / `休憩開始_{氏名}` / `休憩終了_{氏名}`）から
稼働時間を集計させる運用を想定している。
集計の切り口は毎回変わるため、コードで固定するより都度依頼する方が適している。

タイトルに氏名が入るため、共通カレンダーから**人ごとに絞り込んだ集計**もそのまま頼める。

出社・退社のペアから拘束時間を出し、休憩のペアを差し引けば実働時間になる。
同じ日に複数ペアがありうる点に注意すること。

## 開発ルール

このリポジトリで実装を変更する場合は [CLAUDE.md](./CLAUDE.md) のルールに従う。

1. 実装が PLAN.md と食い違うなら、実装より先に PLAN.md を直す
2. PLAN.md の変更で「決定」が変わったなら、同じ作業の中で ADR.md も更新する
3. ADR.md の過去レコードは書き換えない（追記のみ）

ルール2は `.claude/hooks/check-docs-sync.sh`（Stop hook）が機械的に検知する。
PLAN.md が ADR.md より新しいまま応答を終えようとすると差し戻される。
